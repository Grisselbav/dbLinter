The dbLinter Command Line Interface (CLI) can start a language server, run checks and SQL-based tests,
producing various output formats, and format SQL and PL/SQL code.

The CLI is included in the VS Code Extension, but it can also be used standalone, for example within a CI/CD pipeline.

Releases of the dbLinter CLI are published in the [Releases](https://github.com/Grisselbav/dbLinter/releases) section of the dbLinter GitHub repository.

## Installation

import { Steps, Tabs, TabItem } from '@astrojs/starlight/components';

<Tabs>
<TabItem label="Homebrew">
<Steps>
1. Install dbLinter via [Homebrew](https://brew.sh/) (supported on macOS, Linux, and WSL):
    ```bash
    brew install grisselbav/dblinter/dblinter
    ```
   This installs the `dblinter` command from the [homebrew-dbLinter](https://github.com/Grisselbav/homebrew-dbLinter) repository, ready to use on your `PATH`.
2. Optionally set the `JAVA_HOME` environment variable before calling dblinter to control the Java version to use.
3. Optionally set the `JAVA_OPTS` or `DBLINTER_OPTS` environment variable before calling dblinter to control the JVM options to use.
</Steps>
</TabItem>
<TabItem label="ZIP Download">
<Steps>
1. Download `dblinter-x.y.z.zip` from https://github.com/Grisselbav/dbLinter/releases.
2. Extract the contents of the ZIP file to a folder of your choice.
   This will create a folder with the same name as the ZIP file. This folder will contain the following files:
    | File                 | Description                                                       |
    | -------------------- | ----------------------------------------------------------------- |
    | dblinter             | Executable shell script for macOS, Linux                          |
    | dblinter.cmd         | Executable Windows batch file                                     |
    | dblinter-cli.jar     | Executable JAR file, requiring JDK 17 or newer                    |
    | LICENSE.md           | dbLinter License document                                         |
    | THIRD-PARTY.txt      | List of all third party components and their licenses             |
    | THIRD-PARTY-TREE.txt | List of all direct and transitive dependencies and their versions |

3. Add the folder containing the dbLinter executable files to your operating system's path.
4. Optionally set the `JAVA_HOME` environment variable before calling dblinter to control the Java version to use.
5. Optionally set the `JAVA_OPTS` or `DBLINTER_OPTS` environment variable before calling dblinter to control the JVM options to use.
</Steps>
</TabItem>
</Tabs>

## Update

<Tabs>
<TabItem label="Homebrew">
<Steps>
1. Update the Homebrew formulae and upgrade dblinter to the latest version:
    ```bash
    brew update && brew upgrade dblinter
    ```
</Steps>
</TabItem>
<TabItem label="ZIP Download">
<Steps>
1. Download the latest `dblinter-x.y.z.zip` from https://github.com/Grisselbav/dbLinter/releases.
2. Extract the contents of the ZIP file, replacing the files in your existing dblinter folder (the one already on your operating system's path).
</Steps>
</TabItem>
</Tabs>

## Usage

```
Usage: dblinter [<options>] <command> [<args>]

Options:
  --workspace=<dir>            Working directory for the command.
  --repoUrl=<url>              Repository URL.
  --tenantName=<tenant>        Tenant for authentication.
  --userName=<e-mail>          E-mail address for authentication.
  --accessToken=<token>        Access token for authentication.
  --configName=<config>        Configuration for checks and SQL-based tests.
  --connJdbcUrl=<jdbcUrl>      JDBC URL for read-only database access.
  --connUserName=<user>        JDBC user for read-only database access.
  --connPassword=<password>    JDBC password for read-only database access.
  --allowInsecureTls=<boolean> Disable TLS certificate and hostname verification (true, false).
  --logLevel=<level>           Log level (off, error, warning, info, debug, trace).
  --logFile=<logFile>          Name of the log file.
  --logFormat=<format>         Log format (short, ext1, ext2, ext3).
  --clearCacheThreshold=<mb>   ANTLR memory threshold in megabytes.
  --pretty=<boolean>           Pretty print JSON output (true, false).
  --indent=<spaces>            Number of spaces for pretty printing.
  --options=<properties>       Load options from file.

Commands:
  ls                           Start language server.
  check [<args>]               Run static code analysis in current directory.
    --outputFormats=<formats>  Comma-separated list of output formats (vscode,
                               sonarqube, sarif, checkstyle, github, gitlab).
    --outputName=<name>        Base name of the output files.
    --parallel=<n>             Number of files analysed in parallel.
    --newCodeOnly=<boolean>    Only report issues on new and changed lines.
    --referenceBranch=<name>   Reference branch name for new and changed lines.
    <paths...>                 Files and directories to analyse.
  format [<args>]              Format SQL and PL/SQL code in current directory.
    --parallel=<n>             Number of files formatted in parallel.
    --formattingStrategy=<strategy>
                               Overall formatting strategy (lightweight,
                               normalised_compact, normalised_expanded; default:
                               lightweight).
    --dmlStyle=<style>         Style of DML statements (dedicated_keyword_lines,
                               right_aligned_keywords,
                               left_aligned_keywords_align_continuations,
                               left_aligned_keywords_indent_continuations,
                               padded_keywords; default: right_aligned_keywords).
    --parameterDeclarationStyle=<style>
                               Parentheses style for parameter declarations
                               (block, block_next_line, hanging; default: block).
    --inListStyle=<style>      Parentheses style for IN lists. Ignored by lightweight
                               (block, block_next_line, hanging; default: block).
    --subqueryStyle=<style>    Parentheses style for subqueries (block,
                               block_next_line, hanging; default: block).
    --keywordCase=<case>       Case transformation policy for SQL keywords (upper,
                               lower, initcap, wordcap, preserve; default: lower).
    --identifierCase=<case>    Case transformation policy for identifiers (upper,
                               lower, initcap, wordcap, preserve; default: lower).
    --maxLineSize=<n>          Maximum line length in characters (40 to 1000;
                               default: 120).
    --shortExpressionSize=<n>  Maximum length of an expression that is considered
                               short (1 to 1000; default: 60).
    --removeDuplicateBlankLines=<boolean>
                               Collapse consecutive blank lines to a single blank
                               line. Ignored by normalised strategies (true, false;
                               default: true).
    --trimLeadingNewlines=<boolean>
                               Trim blank lines at the start of the file (true,
                               false; default: true).
    --blankLinesBetweenStatementMode=<mode>
                               Strategy for blank lines between statements. Ignored
                               by lightweight (never, always, by_statement_lines;
                               default: by_statement_lines).
    --minStatementLines=<n>    Minimum statement line count used by
                               by_statement_lines mode (1 to 1000; default: 2).
    --preserveSingleLineStatements=<boolean>
                               Preserve statements that fit on one line (true, false;
                               default: true).
    --preserveSingleLineCaseExpressions=<boolean>
                               Preserve CASE expressions that fit on one line (true,
                               false; default: true).
    --leadingComma=<boolean>   Place commas at the beginning of continuation lines
                               (true, false; default: false).
    --leadingConcatenationOperator=<boolean>
                               Place concatenation operators (||) at the beginning of
                               continuation lines (true, false; default: true).
    --leadingLogicalOperator=<boolean>
                               Place logical operators (AND, OR) at the beginning of
                               continuation lines (true, false; default: true).
    --labelOnSeparateLine=<boolean>
                               Place PL/SQL labels on a separate line (true, false;
                               default: true).
    --loopKeywordOnSeparateLine=<boolean>
                               Place the LOOP keyword on a separate line (true,
                               false; default: false).
    --thenKeywordOnSeparateLine=<boolean>
                               Place the THEN keyword on a separate line (true,
                               false; default: false).
    --joinOnKeywordOnSeparateLine=<boolean>
                               Place the ON keyword in joins on a separate line
                               (true, false; default: false).
    --spaceAfterComma=<boolean>
                               Insert a space after commas (true, false; default: true).
    --spaceAfterCommaInDatatypes=<boolean>
                               Insert a space after commas in datatype declarations
                               (true, false; default: false).
    --spaceAroundOperators=<boolean>
                               Insert spaces around operators (true, false; default: true).
    --spaceInsideParentheses=<boolean>
                               Insert spaces immediately inside parentheses (true,
                               false; default: false).
    --spaceAroundParentheses=<boolean>
                               Insert spaces before opening and after closing
                               parentheses (true, false; default: true).
    --spaceBeforeFunctionParentheses=<boolean>
                               Insert a space before function/procedure/method
                               parentheses (true, false; default: false).
    --alignTypeDeclarations=<boolean>
                               Align datatype declarations vertically (true, false;
                               default: true).
    --alignColumnAliases=<boolean>
                               Align column aliases vertically (true, false; default: true).
    --alignTableAliases=<boolean>
                               Align table aliases vertically (true, false; default: false).
    --alignNamedArguments=<boolean>
                               Align named argument operators (=>) vertically (true,
                               false; default: true).
    --alignAssignments=<boolean>
                               Align assignment operators (:=) vertically (true,
                               false; default: true).
    --alignEqualityOperators=<boolean>
                               Align equality operators (=) vertically (true, false;
                               default: false).
    --alignLogicalOperatorsWithKeywords=<boolean>
                               Align logical operators (AND, OR) with keyword columns
                               (true, false; default: true).
    --alignCommentAsterisks=<boolean>
                               Align leading asterisks in multiline comments (true,
                               false; default: true).
    --alignTrailingComments=<boolean>
                               Align trailing single-line comments within a statement
                               (true, false; default: false).
    --tabSize=<n>              Number of spaces per indentation level (1 to 100;
                               default: 3).
    --insertSpaces=<boolean>   Use spaces instead of tabs for indentation (true,
                               false; default: true).
    --trimTrailingWhitespace=<boolean>
                               Trim trailing whitespace on each line (true, false;
                               default: true).
    --insertFinalNewline=<boolean>
                               Insert a newline at the end of the file (true, false;
                               default: true).
    --trimFinalNewlines=<boolean>
                               Trim blank lines at the end of the file (true, false;
                               default: true).
    <paths...>                 Files and directories to format.
  test [<args>]                Run SQL-based tests.
    --outputFormats=<formats>  Comma-separated list of output formats (vscode,
                               junit).
    --outputName=<name>        Base name of the output files without file extension.
    --parallel=<n>             Number of SQL-based tests executed in parallel.
  gen-java [<args>]            Generate custom validator Java project using Maven.
    --outputName=<name>        Root directory name for the Maven project.
    --tenantFilter=<regEx>     Regular expression to filter tenant names.
    --ruleFilter=<regEx>       Regular expression to filter rule names.
    --groupId=<name>           Group ID for the project (e.g. com.company)
    --packageName=<name>       Root package name for the project (e.g. com.company.dblinter)
  gen-utplsql [<args>]         Generate utPLSQL PL/SQL package for SQL-based tests.
    --outputName=<name>        Base name of the output file(s).
    --specExt=<ext>            File extension for the package specification (.sql, .pks)
    --bodyExt=<ext>            File extension for the package body (.sql, .pkb)
    --packageName=<name>       Name of the PL/SQL package.
    --suitePath=<path>         Name of the utPLSQL suite-path.
  export-tenants [<args>]      Export tenants to a JSON file.
    --outputName=<name>        Name of the output file.
    --tenantFilter=<regEx>     Regular expression to filter tenant names.
    --planFilter=<regEx>       Regular expression to filter plan names (Free,
                               Essential, Professional)
  import-tenants [<args>]      Import tenants from a JSON file.
    --inputName=<name>         Name of the input file.
    --tenantFilter=<regEx>     Regular expression to filter tenant names.
  import-validator [<args>]    Import a validator JAR file.
    --inputName=<name>         Name of the validator JAR file.
    --ownerName=<name>         Tenant name owning the validator.
    --parserVersion=<version>  Required IslandSQL parser version.
  version                      Show version information.
  help                         Show help message.
```

## Options

You can save options and command arguments in a property file.

```properties title="dblinter.properties"
# Remote access to the dbLinter repository to read the configuration
tenantName=Demo
userName=philipp.salvisberg+42@gmail.com
accessToken=***
configName=Demo

# Read-only access to database within checks and tests
connJdbcUrl=jdbc:oracle:thin:@localhost:1521/freepdb1
connUserName=dbl_read
connPassword=***
```
