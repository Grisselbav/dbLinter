## Installation

<Tabs>
<TabItem label="via skills CLI (recommended)">
<Steps>
1. From the root of your project, install the skill with [`npx skills`](https://www.npmjs.com/package/skills):
    ```bash
    npx skills add Grisselbav/dbLinter
    ```
   See [Which agent(s) should I select?](#which-agents-should-i-select) for agent selection options.
2. Make sure the `dblinter` CLI itself is installed and authenticated — see the
   [CLI Overview](/dbLinter/tools/cli/cli-overview/#installation). The skill assumes `dblinter` is already on your
   `PATH`.
</Steps>
</TabItem>
<TabItem label="Manual">
<Steps>
1. Copy or symlink the `skills/dblinter` directory from the
   [dbLinter GitHub repository](https://github.com/Grisselbav/dbLinter/tree/main/skills/dblinter) into
   `.agents/skills/dblinter/` at the root of your project (or `~/.agents/skills/dblinter/` to make it available in
   every project). This shared, "universal" location is read directly by most Agent-Skills-compatible agents,
   including OpenAI Codex and GitHub Copilot — see [Which agent(s) should I select?](#which-agents-should-i-select).
2. Claude Code is the exception: it only reads its own `.claude/skills/` directory, not `.agents/skills/`. If you use
   Claude Code, also copy or symlink `skills/dblinter` into `.claude/skills/dblinter/` (or `~/.claude/skills/dblinter/`
   for every project).
3. Make sure the `dblinter` CLI itself is installed and authenticated — see the
   [CLI Overview](/dbLinter/tools/cli/cli-overview/#installation).
</Steps>
</TabItem>
</Tabs>

### Which agent(s) should I select?

Without `-a`, the installer lists all supported agents, including those you have not configured.
When run inside a supported agent, it may install without prompting; check the result.

Pick explicitly to skip the prompt:

```bash
# install for Claude Code and Codex only
npx skills add Grisselbav/dbLinter -a claude-code -a codex

# install for every supported agent
npx skills add Grisselbav/dbLinter -a '*'
```

The installer stores one copy in `.agents/skills/dblinter/` and creates symlinks for agents that require another
directory, such as Claude Code. Updating the shared copy updates the skill for all linked agents.
See [Compatibility](/dbLinter/tools/agent-skill/compatibility/) for directory details.

## Update

<Tabs>
<TabItem label="via skills CLI (recommended)">
<Steps>
1. Update the skill to the latest published version:
    ```bash
    npx skills update dblinter -p
    ```
</Steps>
</TabItem>
<TabItem label="Manual">
<Steps>
1. Re-copy the `skills/dblinter` directory from the
   [dbLinter GitHub repository](https://github.com/Grisselbav/dbLinter/tree/main/skills/dblinter), overwriting the
   version in your agent's skills directory.
</Steps>
</TabItem>
</Tabs>

## Verifying the installation

Confirm `dblinter` appears in your agent's skill list (for example, run `/skills` in Claude Code).
See [Compatibility](/dbLinter/tools/agent-skill/compatibility/) for other agents' instructions. Then try:

```text
Check my SQL files with dblinter and summarize the issues.
```

The agent should select the skill and CLI flags automatically.
See [Usage](/dbLinter/tools/agent-skill/usage/) for more examples.
