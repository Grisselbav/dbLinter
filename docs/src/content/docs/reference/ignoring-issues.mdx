## @dbLinter Ignore Marker Comment

If you are unable to fix a problem or choose not to, you can add a `@dbLinter ignore` marker to indicate that the problem is being intentionally accepted.
This avoids making unnecessary or unsafe changes and keeps the linting output meaningful rather than noisy.

### Syntax

The `@dbLinter` marker comment must be placed within a single-line or multiline comment, and is case-insensitive.

```text
@DBLINTER IGNORE(rule1 [, rule2]...) [comment]
```

The syntax of a rule is as follows:

```text
[tenantName] ruleName
```

If you omit the `tenantName`, the `ruleName` is expected to exist in the `Core` tenant.

### Scope

If the dbLinter marker comment is not the only visible token on a line, the scope is limited to that line only.

If the dbLinter marker comment is the only visible token on a line, the scope is determined by the innermost parser rule context that fully contains the comment.

The following [IslandSQL](https://github.com/IslandSQL/IslandSQL) parser rules are considered:

- [statement](https://islandsql.github.io/IslandSQL/grammar.html#statement)
- [functionDefinition](https://islandsql.github.io/IslandSQL/grammar.html#functionDefinition)
- [procedureDefinition](https://islandsql.github.io/IslandSQL/grammar.html#procedureDefinition)
- [constructorDeclaration](https://islandsql.github.io/IslandSQL/grammar.html#constructorDeclaration)
- [funcDeclInType](https://islandsql.github.io/IslandSQL/grammar.html#funcDeclInType)
- [procDeclInType](https://islandsql.github.io/IslandSQL/grammar.html#procDeclInType)

The following [APEXlang](https://github.com/Grisselbav/APEXlang-Parser) parser rules are considered:

- [componentBody](https://grisselbav.github.io/APEXlang-Parser/grammar.html#componentBody)
- [groupBody](https://grisselbav.github.io/APEXlang-Parser/grammar.html#groupBody)

If the dbLinter marker comment is placed before the first token recognised by the parser, the scope is the whole file.

Please note that APEXlang does not allow comments after a [propertyValue](https://grisselbav.github.io/APEXlang-Parser/grammar.html#propertyValue)
because the comment would be interpreted as part of the property value.

```txt {3} title="Scope: Single-Line"
        /* @dblinter ignore(A-0770) */ embedInFrames: allow

```

```txt {2-4} title="Scope: Group security"

app demo (
    // @dblinter ignore(A-0770)

    }
)
```
```txt {1-6} title="Scope: Component app"
// more...
```

## .dblinterapxignore

Re-exporting an APEX application overwrites comments added to its APEXlang files.
Use a `.dblinterapxignore` file to preserve these exceptions across exports, and commit it to version control alongside your application.
You can still use `@dbLinter ignore()` marker comments in SQL and PL/SQL blocks within APEX files.

### Location

Place `.dblinterapxignore` in the **workspace root**, outside the application export directory.
The CLI and SonarQube plugin each support one workspace root.
VS Code supports multiple workspace roots, each with its own `.dblinterapxignore` file.

### Syntax

Each ignore entry occupies one line:

```text
file-pattern; scope; rule1 [, rule2]... # optional reason
```

- **`file-pattern`** selects APEXlang files using the same [glob patterns as configurations](/dbLinter/tools/web-gui/configurations/#includeexclude-file-patterns).
  For example, `**/pages/page_10.apx` matches that path under any directory.
- **`scope`** selects a component (`region orders ()`), group (`settings {}`), or property (`valueProtected`).
  Nest selectors to narrow the target: `region employees (type)` selects only that component's `type` property.
  Empty `()` or `{}` selects the container and its contents. The outermost selector can match anywhere in the file; `file` selects the whole file.
- **`rules`** is a comma-separated list of rules, with the same optional tenant prefix as [marker comments](#syntax).
  Rules without a tenant prefix belong to `Core`.
- **`#`** starts an optional reason or a comment line.

### Examples

The following `.dblinterapxignore` entries correspond to the [APEXlang marker examples](#apexlang-examples) above.
Each line shows an alternative scope:

```text title=".dblinterapxignore"
**/application.apx; app demo (security {embedInFrames}); A-0770 # Property embedInFrames (single-line marker)
**/application.apx; app demo (security {}); A-0770              # Group security
**/application.apx; app demo (); A-0770                         # Component app
**/application.apx; file; A-0770                                # Whole file
```

A property selector on its own, such as `embedInFrames`, selects all properties with that name in the matching files.
According to the [APEXlang EBNF grammar](https://docs.oracle.com/en/database/oracle/apex/26.1/apxln/apexlang.ebnf)
`embedInFrames` is only defined in the app’s `security` group.
In this case, the first entry in the previous example could be abbreviated as follows without accidentally hiding other issues:

```text title=".dblinterapxignore"
**/application.apx; embedInFrames; A-0770
```
